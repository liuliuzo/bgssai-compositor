# COMP-02 / COMP-04 / COMP-05 实现与验收

本轮版本 0.2.0，保留 bgcomp v1、8192 单边、1677 万画布像素、40 图层、4800 万图层像素和 128 MB 文件限制。源码实现、构建、签名分发及运行验收分别记录。

## COMP-02 自动保存与恢复

完整编辑提交后约 1.5 秒保存恢复副本，连续编辑每 10 秒检查最新完整提交；未完成笔划不写半成品。桌面使用 userData/recovery 两个独立 SHA256 快照，先写临时文件、fsync、重命名；损坏最新代时读取上一有效代。移动端 / 浏览器使用 IndexedDB 的两代事务记录，写入失败或存储配额耗尽保留旧记录。

启动时显示恢复 / 丢弃按钮，恢复为未保存文档且不沿用旧保存路径。正式保存成功、明确丢弃、成功切换文档或确认退出后清理记录。打开 / 保存取消与校验失败保留当前文件和恢复数据。桌面只清理恢复目录里匹配本应用命名的临时文件，不扫描其它项目目录。清理更新下载临时文件并只保留当前候选和回滚安装包。

预计工作集预算为桌面 768 MB、移动 320 MB；估算含现有与待采用项目、图层 Canvas、合成工作面、历史及字符串复制。主要新增 Canvas 和项目解码前检查预算；PNG/JPEG/WebP/BMP 文件头先检查尺寸。历史最多 30 步，预算为 min(96 MB, 工作集预算 / 8)。预算是保守估算，不代表系统实际 RSS 的硬保证；低内存设备仍需要真机压力测试。

## COMP-04 五端与生态

| 平台 | 实现 / 构建 | 运行边界 |
| --- | --- | --- |
| Windows | Electron / NSIS / portable，x64 | 本机运行测试 |
| macOS | Electron / DMG / ZIP，x64 与 arm64 | CI 构建；签名和干净机器验收待做 |
| Linux | Electron / AppImage / DEB，x64 | CI 构建；发行版安装验收待做 |
| iOS | clients/ios 的原生 Xcode / SPM 工程，最低 iOS 17 | macOS CI simulator 构建；签名 IPA / 真机待做 |
| Android | clients/android 的原生 Gradle 工程，API 24+ | 本机 debug APK 构建；真机运行和发布签名待做 |

共同样例是 [fixtures/shared.bgcomp](../../fixtures/shared.bgcomp)：64x64、可编辑红色图层，中心像素应为 RGBA(255,0,0,255)。各端打开，修改图层名称 / 不透明度，保存并跨端重开，确认参数和图层数不变。手机的本地工程包含全部渲染资源，无远程 WebView URL；通过系统文件选择打开，通过 Documents 副本与系统分享保存。软件滤镜在无 Canvas filter 的环境保持非破坏调整；模糊为近似实现，复杂边缘需按容差验收。

可选 Node 24 服务在 `service/server.mjs`。支持完整登录与身份矩阵：离线免登录本地编辑、本地账号密码注册与登录、邮箱与手机号验证码登录、Chat PKCE 授权登录，以及国内第三方 OAuth 渠道（`wechat`、`douyin`、`baidu`、`alipay`）。各渠道按 `channel + sub` 建立本应用独立会话，互不串号并支持独立会话撤销与退出。服务令牌和第三方凭证只在服务内存中，客户端只在内存持有 Compositor 会话。最长两小时，重启需重新登录。

配置对应 `config/application-dev.properties` / `application-prod.properties`：

- `ecosystem.url`：Compositor 服务 HTTPS 根地址，TLS 反代到 127.0.0.1:8787；外部根路径固定。
- `chat.issuer`、`chat.client-id`：登记独立用户端客户端和精确 `${ecosystem.url}/oauth/callback`；public client 可不带 secret，confidential client 仅服务环境设置 `COMPOSITOR_CHAT_CLIENT_SECRET`。
- `hub.url`、`hub.cn.url`、`hub.global.url`、`hub.model`：受控区域 AI 路由根地址与默认模型；服务环境设置 `COMPOSITOR_HUB_KEY`。通过 `GET /api/ai/models` 暴露受控模型目录，支持客户端按模型与区域发起请求，服务端强制校验白名单节点并拦截未授权 URL，错误统一返回可追踪 `request_id` 的友好提示。
- `support.url`、`bot.url`、`downloads.url`：登记统一客服桥接（`product_code=compositor`）、Bot/MCP、五端下载 HTTPS 入口。主进程只打开这些配置来源及受信任 OAuth 来源的外部链接。
- `COMPOSITOR_DATA_DIRECTORY`：仅服务使用的项目目录，按身份通道与用户标识哈希分文件；部署需要限制文件权限、备份及容量监控。

dev / prod 均部署 **develop**，只用不同 properties；服务默认 loopback。配置留空时编辑器不会联系服务。`npm run build:shared` 后执行 `APP_ENV=dev npm run service`（PowerShell 使用 `$env:APP_ENV='dev'`）。

| 服务接口 | 授权 / 行为 |
| --- | --- |
| GET /api/auth/channels | 返回支持的认证通道列表（本地密码、邮箱/手机验证码、Chat PKCE、微信、抖音、百度、支付宝） |
| POST /api/auth/register、/api/auth/login/password | 本地账号密码注册与登录，建立独立会话 |
| POST /api/auth/code/send、/api/auth/code/verify | 邮箱与手机号验证码发送与核验登录，单次有效，建立独立会话 |
| POST /api/auth/begin、/api/auth/oauth/begin、poll、cancel | Chat 及微信/抖音/百度/支付宝 OAuth 授权发起、轮询与取消 |
| PUT /api/grants | sync / ai / bot 布尔值，默认全部 false |
| GET /api/project、PUT /api/project | JSON content + If-Match；冲突 412，不覆盖 |
| GET /api/ai/models、POST /api/ai/text | 返回受控模型目录；按用户所选 `model` 与产品区域受控路由，返回脱敏友好错误与 `request_id` |
| GET/POST /api/support/tickets、POST /api/support/tickets/:id/messages、POST /api/support/webhook | 统一客服桥接（`product_code=compositor`），支持工单创建、消息收发、外发桥接投递、客服回复与状态回调幂等去重及用户归属隔离 |
| POST /api/bot/token、POST /api/pat、GET /api/mcp/tools、POST /api/bot/operate、POST /api/mcp/call | 专用令牌与 PAT 鉴权；支持新建项目、导入/导出资产（`.bgcomp`/`png`/`jpeg`）、新增/更新文字/形状/图像图层、画布与变换/滤镜调整、破坏性操作预览/确认执行及撤销回滚 |
| DELETE /api/session | 撤销当前通道关联令牌、本应用会话及其关联 Bot/PAT 令牌 |

关闭 sync 会删除账户云端项目并使 Bot/MCP 失效；关闭 ai 阻止新请求及返回已撤权的在途结果；关闭 bot 使专用令牌与 PAT 失效。退出会话不会删除已保存云端项目，删除应先撤销 sync。外部 Bot / MCP / 官网接入读取 [Bot 与 MCP 契约](../../integration/bot-app.json)、[OPS-COMP-01/02 特性规格](OPS-COMP-01-02.md) 和 [下载登记](../../distribution/catalog.json)。

## COMP-05 可靠分发与更新

普通 Windows / 跨平台 CI 在 PR / develop 构建并上传 artifact。`npm run release:manifest` 为当前版本的本地产物生成 SHA256SUMS 和 build-manifest.json，记录 HEAD 与工作区是否有修改；不存在 GitHub Release 不影响本地构建证据。

手工 `Controlled signed release` 工作流只允许从 develop 触发，只接受 develop 上已存在的 vX.Y.Z tag，且版本必须匹配 package.json。配置 `compositor-release` environment 的授权人员和 secrets 后，构建 Windows Authenticode、macOS 签名 / 公证、Android 同密钥 APK/AAB、iOS release-testing IPA，五端成功才创建 **draft Release**。iOS release-testing 需要登记验收设备；App Store 分发需要另行走正式提交。

所需受控 secrets：WINDOWS_CSC_LINK / PASSWORD；MAC_CSC_LINK / PASSWORD；APPLE_ID / APPLE_APP_SPECIFIC_PASSWORD / APPLE_TEAM_ID；ANDROID_KEYSTORE_BASE64 / STORE_PASSWORD / KEY_ALIAS / KEY_PASSWORD；IOS_CERT_BASE64 / CERT_PASSWORD / PROFILE_BASE64；RELEASE_ED25519_PRIVATE_KEY。将其配套 **公钥** 放入 `config/update-public-key.pem` 并通过 PR 提交；私钥不得进入仓库或应用。未提供签名凭据时工作流失败，不退化为未签名正式分发。

Ed25519 清单绑定源码 SHA、版本、平台 / 架构、大小、SHA256 和仓库 Release 路径。首个签名 Release 为回滚基线；其后填写 previous_tag，验证上一版清单签名并为各桌面平台生成 updates 清单。应用 `update.feed` 指向该平台更新清单，安装包使用内置公钥校验。首个未签名 0.1.0 没有受信回滚包，因此不允许直接以未签名包作为自动回滚基线。

检查更新拒绝未知签名、过期、降级、错误平台 / 路径和缺失当前版回滚包。下载采用声明大小和 SHA256 流式检查；候选校验失败保留旧应用及旧安装包。Windows NSIS 安装版下载两包后可显式安装：独立 helper 等旧进程退出、执行升级、启动新版本并等待版本回执；失败停止新进程、安装上一版并检查其启动，回滚失败单独报告。portable、macOS、Linux 使用已校验的安装包及保留的上一版手工安装 / 回滚；iOS / Android 通过系统签名分发更新。

干净机器最终验收：安装 -> 打开共同样例 -> 编辑 / 保存 -> 离线重开 -> 升级 -> 强制失败 / 回滚 -> 重开原项目 -> 卸载 -> 按用户选择保留或清理数据。检查签名、SHA256、清单 sourceSha 和 tag 一致；官网、Bot、其它应用下载入口都应取同一签名清单。此流程尚不能仅凭构建和单元测试标记通过。

## 本轮验证

- 单元与服务契约测试：恢复损坏与清理、内存估计、软件滤镜 / 图像头、签名篡改 / 降级 / 过期、下载中断及 installer / startup / rollback 故障分支；全矩阵认证（本地密码、邮箱/手机验证码、Chat PKCE、微信/抖音/百度/支付宝 OAuth）、模型目录与区域受控路由、客服桥接与回调幂等去重、Bot/MCP 全量编辑与预览确认回滚。
- Electron 原有编辑回归；强制终止真实进程后重启恢复、正式保存清理、390x844 手机布局。源码运行使用独立临时 userData，截图已检查。
- TypeScript、Vite、Capacitor Android / iOS sync；Java 21 / SDK 36 的 Android assembleDebug 成功。
- 当前环境无虚拟化扩展，Android emulator acceleration check 失败且没有连接设备；Android 真机验收待做。没有 macOS / Xcode，macOS、Linux、iOS 以远端 CI / 对应机器结果为准。
- Windows 本地分发产物和 packaged / portable 启动结果见 [0.2.0 验证记录](verification-0.2.0.md)。
